Guide 2 of 2 — Configuration

Configuration Editor — User Guide

A five-step wizard for setting SIP transport, ring & audio behavior, notification output device, and codec priorities in properties.json — installed alongside RADIX Phone and launched on demand, no manual JSON editing required.

Start Menu→RADIX Phone→RADIX Phone Configuration

Overview

What this tool does

A short primer before opening it.

RADIX Phone reads its runtime configuration from a single file, Client\json\properties.json, sitting next to the client under the app's install directory. Hand-editing that JSON is error-prone — a stray comma breaks the client on next launch. RadixConfigEditor.exe is a small standalone window that reads the same file, presents every setting as a proper form across five steps, validates each field as you type, and writes the file back out only once you explicitly save.

It ships as its own executable at {app}\ConfigEditor\RadixConfigEditor.exe, installed and uninstalled together with RADIX Phone itself, with its own Start Menu shortcut.

Before you start

Launching the editor

Two things worth knowing before the window even opens.

Always runs elevated

The editor's shortcut always triggers a UAC prompt, even just to open it. This is deliberate — saving a change offers to restart the RADIX Phone Windows Service on the spot (see Applying changes below), and that requires administrator rights. There's no way to skip the prompt; approve it to continue.

Reopening later

If properties.json already exists from a previous run or from Setup, the editor loads your existing values into every field instead of starting from defaults — nothing is reset just by opening the tool again.

Step 1 of 5

Transport

Which SIP protocol and port the client registers with.

Choose UDP, TCP, or TLS — only the selected protocol keeps a port value; the other two are cleared in the saved file. Switching protocol swaps in that protocol's usual default port (5060 for UDP/TCP, 5061 for TLS), which you can still override. Discover global address (NAT) controls whether the client attempts to resolve its public-facing address for NAT traversal.

Step 2 of 5

Ring & Audio Settings

Everything about how (and whether) an incoming call rings.

Turn ring notifications off entirely with No Ring Notification, or leave the built-in ringtone via Use default ring music. Unchecking it enables a file picker for a custom .wav — the field and Browse button are disabled, not hidden, while the default is in use, and checking the default back on clears whatever custom path was set. Play notifications on speaker routes notification sounds to a specific output device chosen on the next step, rather than the wave mapper's default device.

Validated before you can leave

Ring volume (0–100), max ring time (non-negative), and — when a custom file is in use — the ring music path being non-empty are all checked live, not just on Save.

Step 3 of 5 — conditional

Notification Speaker

Only shown when "Play notifications on speaker" is checked.

Lists every audio output device Windows currently reports, refreshed automatically if a device is plugged in or removed while this page is open. Pick one to route notification sounds to it specifically, instead of whatever the system's default output happens to be.

Step 4 of 5

Codec Priorities

Which audio codecs the client offers, and in what order.

Every row is a codec entry: toggle it on or off, and set a priority from 0–255 — higher numbers are preferred first during negotiation. Rows sort by priority automatically. Drag the handle on the left to reorder manually, or use + Add Codec to register one not already listed.

Step 5 of 5

Review & Save

The exact JSON that's about to be written, before it's written.

Every earlier step's answers are assembled into the final properties.json and shown here read-only — nothing on this screen is hand-editable, by design, so what you saw on the previous four pages is guaranteed to be what gets saved. Validate re-runs every check against the assembled document on demand. Clicking Save (Next becomes Save on this last step) writes the file only if validation passes; otherwise the specific issues are listed instead.

After saving

Applying changes: the service restart prompt

Saving the file and applying it to a running client are two different moments — this prompt is what bridges them.

RADIX Phone runs as a Windows Service, so it only picks up a changed properties.json on its next start. The moment Save succeeds, the editor asks directly whether to restart that service now:

  1. Restart Now
    The window switches to a live status line — Stopping…, then Starting… — while the service actually restarts. Once it's confirmed running again, the window closes on its own a moment later.
  2. Restart Later
    The file stays saved as-is; the window just closes. The running service keeps its old configuration in memory until it's restarted some other way — manually, or at next reboot.
If the restart fails

A failure — the service missing, access denied, or a stop/start that times out after 30 seconds — is reported in plain language on that same status line, and the window is left open rather than closing, so nothing is left ambiguous about whether the new config actually took effect.

Under the hood

What Setup installs alongside it

Relevant if you're troubleshooting a machine where the editor won't launch.

The editor is published self-contained, so it carries its own copy of the .NET 8 runtime — no separate runtime install is required for it specifically. RADIX Phone itself, being built against the older .NET Framework, still needs these, which Setup installs automatically only when missing:

  • ✓ .NET Framework 4.8.1
  • ✓ Visual C++ 2015–2022 Redistributable (x64)
  • ✓ Visual C++ 2015–2022 Redistributable (x86)
